# 观行知意：人体日常行为识别挑战赛

## 一、这道题要做什么？

**给模型看一小段人的动作，让它判断这个人在做什么，从固定的40种日常动作中选择一种。**

例如，一段连续画面中，一个人把杯子举到嘴边，再放下，模型需要把这段动作识别为“喝水”。本题的结果是一个动作类别。

参赛队伍需要完成一套可以运行的识别程序：读取动作片段，处理图片，训练分类模型，再用训练好的模型识别新的片段。可以研究怎样取帧、怎样结合深度图和红外图、怎样改进模型，以及怎样提高识别速度。

建议具备Python、PyTorch和图像处理基础。每队提供**100元AutoDL算力券**，可用于租用GPU训练模型。

## 二、会拿到什么数据？

### 2.1 一个样本是一段动作

本题使用CUHK-X数据中的**深度图和红外图**。每个样本是一段已经拆成图片的短视频，包含两套按时间同步的画面：

| 图片类型 | 文件夹名称 | 可以怎样理解 |
| --- | --- | --- |
| 伪彩深度图 | `Depth_Color/` | 用颜色编码物体与相机的距离，提供人体轮廓和空间信息；颜色不是物体的真实颜色 |
| 红外图 | `IR/` | 同一时刻的8位灰度画面，提供另一种人体和场景信息 |

每段最多提供**32对同步图片**，原始分辨率为**304×228**。模型需要综合一段连续画面判断动作。

### 2.2 训练、验证和正式测试

| 数据 | 数量 | 用途 |
| --- | ---: | --- |
| 训练集 | **1995段** | 根据已知动作标签训练模型、更新模型参数 |
| 公开验证集 | **466段** | 检查识别效果，比较方法、选择参数和分析错例 |
| 组织方测试集 | **470段** | 由组织方在独立评测环境中统一测评，片段和标签不向选手开放 |

训练集和公开验证集均提供动作标签。三个集合**按人物划分，人物不跨集合**，用于检查模型能否识别未在训练中见过的人做的动作。

数据包`wujie-classification-depth-ir-data.zip`约**4.90 GB**，在比赛QQ群中提供。解压后有`train/`和`validation/`，各自包含`manifest.json`与动作片段目录。

`manifest.json`是数据清单：`samples`记录各段数据的位置和标签，`classes`给出固定的40个类别。**类别编号0—39与`classes`数组的位置对应，预测和提交时必须保持这一顺序。**

## 三、选手怎样开发自己的模型？

### 3.1 从配套示例开始

**[下载人体行为识别开发包](/api/markdown-assets/cf37e5ba-69c8-4f3e-b9ae-db59c518f61c)**

开发包提供环境安装、数据整理、模型微调、验证集预测和错例分析程序。完整操作步骤见[开发教程第11章](/news/community-00d3bcac-0350-43f4-b91c-d2173e99d592#11-人体行为识别开发与提交)。

推荐先运行配套的**R(2+1)D-34视频分类模型**。它用连续画面预测动作类别。“公开预训练微调”是指先加载公开的模型参数，再用本题训练集继续训练。训练后保存的**模型权重**文件记录了模型学到的参数，测评时必须与相应代码一起使用。队伍也可以选择其他模型或从零训练。

默认示例从每段中取**16帧**，缩放到**128×128**，将深度伪彩图的3个通道与IR的1个通道合成**4通道输入**。这些是示例配置，可以调整；原始数据最多32帧、304×228的规格不等于必须使用的模型输入规格。

### 3.2 建议的开发顺序

1. **准备环境和数据**：使用Linux或WSL、Python 3.10，安装开发包依赖并解压数据。
2. **先跑通示例**：生成训练清单、制作缓存、下载公开预训练权重，再运行微调。
3. **检查验证效果**：在466段公开验证集上生成预测CSV，查看准确率、各类表现和错例。
4. **逐步改进**：尝试不同取帧、输入大小、人物裁剪、模态融合或模型结构，每次保留配置和实验记录。
5. **确定最终版本**：用同一份代码、配置和权重生成最终验证结果，准备要上传的材料，通过QQ发送权重给赛事负责人。

这题的训练在选手本地或租用的GPU上完成。正式测评时只运行训练好的模型进行识别，**离线运行，不调用在线大模型API**。

### 3.3 模型与数据使用规则

- 可以使用提供的深度图、IR或两者融合，并调整取帧数量与位置、人物裁剪和输入尺寸。
- 本题训练与推理仅使用提供的**深度图和IR**；额外模态不用于训练、辅助监督、蒸馏或推理。训练集用于参数学习，公开验证集用于方法比较与参数选择。
- **允许使用通用公开预训练权重，禁止使用在CUHK-X上预训练或微调过的外部权重。** 参赛队伍可使用本届提供的训练集自行训练或微调；公开验证集仅用于评估和模型选择。报告中列明模型名称、权重来源、许可证、SHA256、训练数据和微调设置。
- 组织方测试片段及标签不参与训练、伪标签生成或模型选择；公开源数据中本届提供范围以外的CUHK片段不作为额外训练数据。
- 所有参与推理的模型参数合计不超过**100M（1亿）**，包括分类器、人物检测器和冻结参数。

## 四、程序接收什么、返回什么？

代码ZIP根目录须有`inference.py`和`config.json`。在`inference.py`中定义`Model`类，接口为：

```python
model = Model(config, device)
scores = model.predict(sample_path)
```

`sample_path`指向当前一个动作片段的目录，里面有同步的`Depth_Color/`与`IR/`图片。程序自行完成取帧、缩放、人物检测和分类。

`predict`返回**按固定类别顺序排列的40个有限数值**。第0个值对应第0类，依此类推；测评程序取分数最高的类别作为预测结果。不要求这些数值加起来为1。

本地预测程序`predict.py`会将这些分数转换为类别编号，生成列名为`sample_id,predicted_class`的CSV，类别编号范围为0—39。

代码应读取配置中的权重路径，不把自己电脑上的绝对路径写死。配套示例通过`config["weights_path"]`加载模型，运行入口负责解析`config.json`里的`weights_file`。依赖采用配套环境版本；额外依赖须在测评前联系组织方登记，测评过程中不临时联网安装或下载模型。

## 六、评分标准

比赛由**模型或智能体实际表现、技术路线说明和现场答辩**三部分构成，模型或智能体实际表现原始分采用百分制；两个人工项先加权为实际得分，再录入统一评分表。

### 6.1 模型或智能体实际表现（50%）

模型或智能体实际表现根据识别模型在组织方470段测试集上的表现自动计分。公开验证集用于开发调试、方法比较和报告中的实验分析，验证集分数不直接作为正式成绩。

客观测评原始分满分100分，由以下部分构成：

| 评分项目 | 分值 | 评分依据 |
| --- | ---: | --- |
| 基准分 | 60分 | 识别准确率相对于参考模型的表现 |
| 提升分 | 20分 | 识别准确率相对于参考模型的提升 |
| 类别表现 | 10分 | 固定40类动作的Macro F1 |
| 推理效率 | 10分 | 结合识别表现考察平均推理延迟 |

准确率表示全部片段中预测正确的比例；Macro F1分别计算40类动作的F1后取平均；平均推理延迟表示识别一个动作片段的平均耗时。

单次运行上限为**1800秒（30分钟）**，包括领取后的程序包与权重准备、模型初始化和推理，排队不计时。首个样本用于预热，其预测计入准确率，耗时不计入平均推理延迟。

**详细公式、参考值与计时规则，请参阅：[观行知意：模型测评计分规则.pdf](/api/markdown-assets/c5f5f808-2844-479e-9121-a537f2b7be49)。** 参考值在开放测评前固定。

### 6.2 技术路线说明（10%）

参赛队伍须提交技术报告 PDF，介绍智能体的设计思路、核心方法、工程实现及实验成果。


**[下载技术报告模板.docx](/api/markdown-assets/c727779d-75d8-4ffe-9c3c-0636c8bdf7e8)**

#### （1）报告格式

* 使用中文撰写，正文 **3000～5000 字**，不包含封面、目录、参考文献和附录。
* 按赛事提供的技术路线说明模板编排，最终提交 PDF 格式。
* 报告应包含摘要、正文、总结及参考文献。
* 鼓励使用系统架构图、算法流程图、实验图表和环境截图展示方案与结果。
* 引用论文、开源代码和技术工具时，应注明来源及实际使用方式。

#### （2）报告评审重点

技术路线说明主要从以下方面进行综合评价：

* **方案设计**：任务理解、技术选择、系统架构及关键方法的合理性。
* **工程实现**：功能实现程度、模块协作、代码质量及可复现性。
* **实验分析**：实验设计、结果展示、数据分析与改进思路。
* **技术表达**：报告结构、图表质量、引用规范及团队贡献说明。

### 6.3 现场答辩（40%）

答辩包括方案介绍、技术亮点、成果展示、现场评委问答等环节。

具体答辩时间、地点和形式另行通知。

### 6.4 最终成绩

比赛最终成绩采用加权计算：

**最终成绩 = 自动表现原始分 × 50% + 技术路线说明实际分（0—10）+ 现场答辩实际分（0—40）。**

最终成绩满分为 100 分。
