# 无界探索：开放世界智能体挑战赛

## 一、任务背景与目标

开放世界环境具有空间广阔、资源分布未知、任务依赖复杂等特点，对智能体的环境感知、长期规划和自主决策能力提出了挑战。

本赛题基于 MineDojo 开放世界模拟环境。参赛队伍需要开发一个能够自主探索环境、采集资源、制作工具并推进科技树的智能体（Agent）。

智能体从空背包开始，通过观察环境画面与自身状态，自主决定行动，逐步完成从木制工具到铁制工具的科技发展过程，最终目标为**成功制作并获得铁镐（`iron_pickaxe`）**。

参赛队伍可自主选择技术路线，包括大语言模型、多模态模型、规则策略、任务规划、环境记忆、技能库及代码执行工具等。鼓励结合不同方法，构建具备持续决策、任务执行和自主纠错能力的智能体系统。

## 二、任务内容

### 2.1 科技树任务

智能体需要在开放世界中自主完成资源发现、地形探索、材料采集、工具制作和矿石冶炼，逐步推进木制、石器和铁器三个科技阶段。

| 科技阶段 | 目标物品 | 物品标识符            |
| ---- | ---- | ---------------- |
| 木制阶段 | 原木   | `log` / `log2`   |
|      | 木板   | `planks`         |
|      | 木棍   | `stick`          |
|      | 工作台  | `crafting_table` |
|      | 木镐   | `wooden_pickaxe` |
| 石器阶段 | 圆石   | `cobblestone`    |
|      | 石镐   | `stone_pickaxe`  |
|      | 熔炉   | `furnace`        |
| 铁器阶段 | 铁矿石  | `iron_ore`       |
|      | 铁锭   | `iron_ingot`     |
|      | 铁镐   | `iron_pickaxe`   |

上述目标物品构成科技树里程碑。智能体可根据环境条件自主安排探索路线、资源获取顺序和制作策略。

### 2.2 支线任务

除科技树任务外，智能体还可完成以下支线任务，获得额外分数：

* 获取煤炭或木炭；
* 获取普通火把；
* 在模拟世界中成功放置普通火把。

### 2.3 任务达成

目标物品通过正常环境交互合法进入背包或装备栏，并由环境状态或物品获取事件确认后，即视为达成对应里程碑。

每项里程碑和支线任务在首次达成时计分，后续消耗、丢弃或遗失物品不影响已获得的分数。

## 三、测评环境与运行方式

正式测评采用多个隐藏随机种子，每个种子对应一个独立的开放世界。智能体在每个世界中均从相同的初始配置开始，完成科技树推进与支线任务。各局独立运行、独立计分。

每局实际运行时间上限为 **3600 秒**，包含智能体推理、模型调用和环境交互等全部耗时。

每局 LLM Token 消耗上限为 **5,000,000 Token（5M）**。Token 消耗统计范围为智能体通过官方指定 LLM 调用端口发起的全部 LLM 调用，以比赛官方统一指定 API 平台的计数结果为准。各局 Token 消耗独立累计。

智能体通过环境接口执行动作，每次底层 `env.step` 调用计为一个环境步，累计步数用于计算任务完成效率。LLM 推理、模型调用和 Token 消耗不计入环境步数，也不直接计分。

智能体死亡后可在当前世界中复活并继续探索，累计步数继续计算，死亡次数计入评分。

每局在以下任一条件满足时结束：

1. 智能体首次合法获得铁镐；
2. 实际运行时间达到 **3600 秒**；
3. LLM Token 累计消耗达到 **5,000,000 Token（5M）**。

达到运行时间或 Token 消耗上限时，测评立即终止，当前未完成的环境步不计入累计步数。触达 Token 上限的那次 LLM 调用所产生的后续动作不再执行。

## 五、提交材料

参赛队伍需提交以下材料：

1. **智能体代码 ZIP**：包含 Agent 程序、配置文件及运行所需模块。
2. **网页作品说明**：简要介绍项目结构、技术路线、运行方式、依赖及第三方引用。
3. **技术路线说明 PDF**：介绍系统设计、关键算法、工程实现、实验结果及分析。

参赛队伍可通过公开练习环境进行本地实验，并在比赛平台提交最终版本与相关材料，由组织方统一评测与评审。

代码组织、运行环境、资源限制及提交流程请参阅开发包和 Docker 安装与比赛镜像使用教程。

## 六、评分标准

比赛由**模型或智能体实际表现、技术路线说明和现场答辩**三部分构成，模型或智能体实际表现原始分采用百分制；两个人工项先加权为实际得分，再录入统一评分表。

### 6.1 模型或智能体实际表现（50%）

模型或智能体实际表现根据智能体在隐藏种子世界中的实际表现自动计分。

每局客观得分由以下部分构成：

| 评分项目  |       分值 | 评分依据             |
| ----- | -------: | ---------------- |
| 科技树分  |     55 分 | 11 项科技里程碑的完成情况   |
| 支线任务分 |      5 分 | 煤炭或木炭获取、火把获取与放置  |
| 效率分   |     40 分 | 木制、石器、铁器检查点的完成步数 |
| 死亡扣分  | 最多扣 10 分 | 每次死亡扣 2 分        |

其中，科技树分根据目标物品的合法获得情况计算，首次合法获得铁镐时，科技树分计为满分。效率分根据木镐、石镐与熔炉、铁镐三个检查点的达成步数计算，鼓励智能体高效完成长期任务。

每局得分限定在 0～100 分之间，所有测试世界的得分取算术平均，作为最终模型或智能体实际表现成绩。

**各里程碑分值、效率分计算公式、检查点定义、测评终止条件及完整计分方法，请参阅：**

**[下载《无界探索：开放世界智能体挑战赛——智能体测评计分规则》（PDF）](/api/markdown-assets/5caa3241-05f7-4f80-bf79-38d2f08472f2)**

### 6.2 技术路线说明（10%）

参赛队伍须提交技术报告 PDF，介绍智能体的设计思路、核心方法、工程实现及实验成果。


**[下载技术报告模板.docx](/api/markdown-assets/c727779d-75d8-4ffe-9c3c-0636c8bdf7e8)**

#### （1）报告格式

* 使用中文撰写，正文 **3000～5000 字**，不包含封面、目录、参考文献和附录。
* 按赛事提供的技术路线说明模板编排，最终提交 PDF 格式。
* 报告应包含摘要、正文、总结及参考文献。
* 鼓励使用系统架构图、算法流程图、实验图表和环境截图展示方案与结果。
* 引用论文、开源代码和技术工具时，应注明来源及实际使用方式。

#### （2）报告评审重点

技术路线说明主要从以下方面进行综合评价：

* **方案设计**：任务理解、技术选择、系统架构及关键方法的合理性。
* **工程实现**：功能实现程度、模块协作、代码质量及可复现性。
* **实验分析**：实验设计、结果展示、数据分析与改进思路。
* **技术表达**：报告结构、图表质量、引用规范及团队贡献说明。

### 6.3 现场答辩（40%）

答辩包括方案介绍、技术亮点、成果展示、现场评委问答等环节。

具体答辩时间、地点和形式另行通知。

### 6.4 最终成绩

比赛最终成绩采用加权计算：

**最终成绩 = 自动表现原始分 × 50% + 技术路线说明实际分（0—10）+ 现场答辩实际分（0—40）。**

最终成绩满分为 100 分。

## 七、参赛规范

智能体应自主完成环境感知、任务决策和行动执行。参赛队伍可采用规则策略、机器学习、模型推理、多模块协作等技术方案。

环境交互通过规定接口完成，LLM 调用统一通过赛事指定端口进行，Token 消耗按官方 API 平台的计数结果累计。参赛作品应遵守公平测评要求，相关行为规范及违规处理办法详见上文提到的《无界探索：开放世界智能体挑战赛——智能体测评计分规则》。

### 开发包与正式提交说明

开发包不包含 Markdown 文档、自动打包工具或启动脚本。使用说明集中在[开发教程](/news/community-00d3bcac-0350-43f4-b91c-d2173e99d592)。代码与依赖文件由队伍手动压缩为 ZIP；技术报告 PDF 为必交材料，网页作品说明不能替代 PDF。三题均直接正式提交，由评委或管理员统一测评或导入结果，不要求官网自测或绑定试运行记录。
