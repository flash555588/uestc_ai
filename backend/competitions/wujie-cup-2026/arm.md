# 慧眼巧手：机械臂智能体操作挑战赛

## 一、任务背景与目标

本赛题基于 LIBERO 仿真环境。参赛队伍需要开发一个能够理解自然语言指令、观察相机画面并控制 Panda 机械臂的智能体，完成抓取、放置和多物体组合操作。

队伍可自主选择技术路线，包括规则策略、机器学习、多模态模型、任务规划和技能库等，根据执行反馈持续改进操作效果。

## 二、任务内容

正式测评共五题，前三题公开，后两题为非公开任务。

| 公开任务 | 操作目标 | 最大控制步数 | 参考步数 |
| --- | --- | ---: | ---: |
| 黑碗放盘 | 将桌面中央的黑碗放到盘子上 | 600 | 300 |
| 汤罐入篮 | 将字母汤罐放入篮子 | 600 | 300 |
| 双物品入篮 | 将字母汤罐和番茄酱放入篮子 | 1000 | 600 |

前三题对应官方 `task_order_index=0` 顺序下的 `libero_spatial / 2`、`libero_object / 0`、`libero_10 / 0`。开发包提供初始状态 0、1、2，队伍也可使用公开任务的其他初始状态开展实验。

**第 4、5 题的具体任务、物体组合与布局不公开，由组织方统一保存并用于正式测评。** 两题使用与开发环境一致的机械臂、相机、观察字段和动作接口。

各题独立重置，环境状态不跨题保留。同轮所有队伍使用相同任务、初始状态、模型/API 条件及运行预算。

## 三、测评环境与运行方式

正式测评使用同一份冻结作品运行五题，默认整轮限时 **7200 秒、最多 500 次模型调用**，以赛事公布并冻结的配置为准。

| 项目 | 限制 |
| --- | --- |
| 选手程序 | 4 CPU、2 GiB 内存 |
| LIBERO 仿真环境 | 独立容器、3 GiB 内存 |
| 整组容器 | 合计最多 6 GiB，不使用交换空间 |
| GPU | 无 |
| 提交 ZIP | 不超过 20 MiB、256 个文件，解压后不超过 64 MiB |

额外依赖、GPU 或大权重需求须联系赛事方，默认的 CPU 测评不临时安装依赖。

每次实际执行的底层 `env.step` 计为一个控制步，技能展开、等待、无效动作和重试均计入。同题内累计计步，下一题重新计数；模型推理、API 等待、视频编码和环境初始化不计入控制步数。

每题在全部目标同时满足或预算耗尽时结束。系统记录各题结果、成功率、控制步数、执行耗时和无效动作，并保存双视角回放及动作轨迹。

## 四、开发资源与技术说明

**[下载 LIBERO 开发包](/api/markdown-assets/5b339187-ef40-44c4-82af-b5aabd156def)**

**[下载配套离线环境](https://github.com/Takamatsu-Hikaru/uestc_ai/releases/download/libero-20261018-final/wujie-libero-practice-20261018-final.tar.gz)** （更推荐参考[Docker安装与比赛镜像使用教程](https://uestcai.top/news/community-00d3bcac-0350-43f4-b91c-d2173e99d592)的Docker镜像）

开发包包含图像模型 harness、机械臂动作工具、公开练习配置、最近邻策略示例及本地练习入口。默认 `agent.py` 会调用视觉模型，根据任务、画面和反馈选择动作技能，`robot_skills.py` 将技能展开为逐步七维控制动作。默认示例需要配置模型名称与个人开发密钥，不保证完成任务。


### 4.1 环境配置

环境采用 Python 3.11、robosuite 1.4.0、MuJoCo 2.3.7、NumPy 1.26.4，使用 20 Hz 控制与 CPU 无头渲染。

Agent 接收外部与腕部两路 128×128 图像；回放以每路 256×256 录制，合成为 512×256 双视角视频，按仿真时间播放。环境关闭多重采样、实时阴影和反射，保留物理状态、纹理、相机和原生成功判定。

默认选手容器包含 NumPy、Pillow、requests，不要求训练模型。模仿学习代码与演示数据可参考 [LIBERO 官方项目](https://github.com/Lifelong-Robot-Learning/LIBERO)。

### 4.2 智能体接口

ZIP 根目录须包含 `agent.py` 和 `config.json`。程序定义 `Agent.act(observation)`，可选实现 `configure(config)` 和 `reset(goal)`。

`reset` 提供 `instruction`、`suite`、`task_name`、`max_steps`，不提供测试种子或初始状态编号。

观察包含两路正向 JPEG 图像 `images_jpeg_base64`（`agentview`、`robot0_eye_in_hand`），以及 `eef_position`、`eef_quaternion`、`gripper_position`、`joint_position`、`step`、`last_action_valid` 和 `control`。物体真值、奖励与成功标志仅供评测端使用；执行历史由参赛程序自行保存。

每次 `act` 返回七维浮点动作：

```text
[dx, dy, dz, rx, ry, rz, g]
```

各项须为有限值且位于 `[-1, 1]`。平移是世界坐标系下的相对目标增量，每轴最多 0.05 米；旋转为相对轴角，每轴最多 0.5 弧度。`g=1` 关闭夹爪，`g=-1` 打开；`eef_quaternion` 按 `xyzw` 排列。

一次动作对应一个控制步。实际位移受动力学和碰撞影响，重复动作会逐步更新目标。非法动作按零位移、零旋转执行，保留上一条夹爪命令，并计入无效动作数。

### 4.3 模型接入

模型调用使用 `model_api.py`。本地练习可使用 [模型 API 平台](https://api.uestcai.top)的个人开发密钥，预算由开发者设置；正式测评使用组织方指定的统一模型，五题共享调用预算。

`config.json` 仅包含 `model` 和 `agent` 两个对象：前者填写 `name`、`api_url`、`api_key`，后者保存策略参数。例如：

```json
{
  "model": {
    "name": "填写可用的完整视觉模型名称",
    "api_url": "https://api.uestcai.top/v1/chat/completions",
    "api_key": ""
  },
  "agent": {
    "max_output_tokens": 4096,
    "api_timeout": 135,
    "thinking": false
  }
}
```

个人密钥建议仅通过环境变量提供，不能写入提交代码或其他资源。默认示例需要模型支持图片输入；`max_output_tokens` 为单次输出上限，`api_timeout` 为请求等待秒数，应符合所用模型和平台要求。正式测评由平台在运行副本中替换 `model`，保留 `agent` 和原始作品文件。

正式测评注入 `EVALUATION_API_URL`、`EVALUATION_API_TOKEN`，请求头为 `X-Evaluation-API-Token`；随包的 `model_api.py` 处理鉴权，不要在代码中写死个人密钥、模型名称或请求地址。

同一轮测试中创建一次 Agent 并调用一次 `configure`，每题开始时调用 `reset`，随后逐步调用 `act`。各题仿真世界独立初始化；默认策略会在 `reset` 中清理任务记忆和技能状态。模型调用助手不会自动重试，调用失败会抛出异常，可通过 `last_response` 查看请求编号、结束原因和用量。

## 五、提交材料与流程

参赛队伍需提交以下材料：

1. **智能体代码 ZIP**：包含 Agent 程序、配置文件及运行所需模块。
2. **网页作品说明**：简要介绍项目结构、技术路线、运行方式、模型、权重、依赖及第三方引用。
3. **技术报告 PDF**：介绍系统设计、关键方法、工程实现、实验结果及分析。

演示视频、补充实验等材料可选。作品可直接正式提交，无须官网自测或关联试运行记录。

**提交截止前，队伍可修改作品并重新正式提交，以截止时最后一次正式提交的版本为准。** 新版本覆盖旧稿，内容变化后原评分会清除。保存为草稿会退出正式提交状态，队伍须在截止前再次完成正式提交。

提交截止后，作品内容及附件锁定，用于统一测评和评审。评委或管理员可启动测评，也可分批导入线下结果；五题结果完整校验后生成正式自动分。

成绩经确认及代码审阅通过后统一发布，队伍可查看成绩与评测记录。

## 六、评分标准

比赛由**自动测评、技术报告和口头答辩**三部分构成，各项得分均采用百分制。

### 6.1 自动测评（50%）

自动测评根据智能体在五道正式任务中的实际表现计分，原始分满分 100 分，其中完成分 60 分、效率分 40 分。

| 题目 | 完成分 | 效率分 |
| --- | ---: | ---: |
| 第 1 题：黑碗放盘 | 10 | 20/3 |
| 第 2 题：汤罐入篮 | 10 | 20/3 |
| 第 3 题：双物品入篮 | 10 | 20/3 |
| 第 4 题：非公开任务 | 15 | 10 |
| 第 5 题：非公开任务 | 15 | 10 |
| 合计 | 60 | 40 |

同题内多个目标平分该题分值。目标须在本题结束时仍满足 LIBERO 原生成功条件，才能获得完成分和效率分。

设题目完成分上限为 `W`、目标数为 `n`、参考步数为 `B`，某目标的有效达成步数为 `T`，则：

```text
已完成目标得分 = W/n + 2W/(3n) × clip(1.5 − T/B, 0, 1)
未完成目标得分 = 0
```

`clip(x, 0, 1)` 将结果限制在 0 到 1。目标在半倍参考步数内完成可得全部效率分，在参考步数完成得一半效率分，达到 1.5 倍参考步数时效率分为 0。

同题内各目标的达成步数均从开局累计，共用该题参考步数。参考值依据已完成轨迹向上取整到百步确定，同轮保持一致；最大控制步数、运行时间和调用额度另行限制。

物品完成放置后若离开目标位置，该目标失分；重新放好后，以最后一段持续满足条件直至本题结束的区间起点作为有效达成步数。初始状态不得已有完成目标。

黑碗放盘的原生成功条件为：碗与盘接触、碗中心高于盘中心，且两者中心的水平距离小于 3 cm。评测端在每个控制步检查目标状态。

五题得分相加得到自动测评原始分。缺失或未完成目标计 0 分，各题权重保持不变；开发过程中的历史最好成绩不能拼入正式成绩。

### 6.2 技术路线说明（10%）

参赛队伍须提交技术报告 PDF，介绍智能体的设计思路、核心方法、工程实现及实验成果。


**[下载技术报告模板.docx](/api/markdown-assets/c727779d-75d8-4ffe-9c3c-0636c8bdf7e8)**

#### （1）报告格式

* 使用中文撰写，正文 **3000～5000 字**，不包含封面、目录、参考文献和附录。
* 按赛事提供的技术路线说明模板编排，最终提交 PDF 格式。
* 报告应包含摘要、正文、总结及参考文献。
* 鼓励使用系统架构图、算法流程图、实验图表和环境截图展示方案与结果。
* 引用论文、开源代码和技术工具时，应注明来源及实际使用方式。

#### （2）报告评审重点

技术路线说明主要从以下方面进行综合评价：

* **方案设计**：任务理解、技术选择、系统架构及关键方法的合理性。
* **工程实现**：功能实现程度、模块协作、代码质量及可复现性。
* **实验分析**：实验设计、结果展示、数据分析与改进思路。
* **技术表达**：报告结构、图表质量、引用规范及团队贡献说明。

### 6.3 现场答辩（40%）

答辩包括方案介绍、技术亮点、成果展示、现场评委问答等环节。

具体答辩时间、地点和形式另行通知。

### 6.4 最终成绩

**最终成绩＝自动测评原始分×50%＋技术报告成绩×10%＋答辩成绩×40%**

最终成绩满分 100 分，计算保留完整精度，展示保留两位小数。

代码审阅判定通过或不通过，不单独计分；通过后采用正式测评成绩。

## 七、参赛规范与故障处理

参赛程序通过规定接口控制机械臂，根据公开观察自主判断阶段并调整动作。仿真环境与选手程序运行于独立容器，私有场景及结果目录不向选手挂载。

代码审阅核对输入来源、提交版本、依赖与复现情况，并记录不通过原因。

组织方环境、测评服务或 API 故障，由组织方核查后使用相同冻结作品和配置重测。参赛程序错误依据日志核查，正常预算耗尽按结束状态结算；异常中断保留目标状态与轨迹，经核查后发布结果。
